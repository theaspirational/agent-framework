## 1. Summary and recommended interface (Q1, Q3)

[src] Investigation base: `git rev-parse HEAD` returned `4976c67d5c7916a15046c627b68913994c33b3cb`. All source citations below refer exclusively to that pinned commit (0.27.0), not a newer main. This is a source-bounded design investigation, not a runtime proof. No source changes or tests were made.

[prop] Add a distinct, asynchronous, host-owned admission hook. Require it only on explicitly configured connections, and bind each installed hook to `(connectionId, connection-instance token, transportEpoch)`. Decide separately for each inbound channel message, push event, or inference request. A refusal ends processing before application admission effects. Do not repurpose either existing callback. The strict opt-in path must also interpose before transport holding and push read-tap effects; merely inserting a callback in the registry is insufficient.

[prop] Suggested TypeScript-style API; names here are local API names, not wire fields or stamp spellings. `DeepReadonly` and the opaque branded types are illustrative:

```ts
type AdmissionLane = 'channels/incoming' | 'push/event' | 'inference/request';
type ConnectionKey = Readonly<{
  connectionId: string;
  instance: ConnectionInstanceToken; // framework-issued, unique per object lifetime
  transportEpoch: number;
}>;
type RefusalCode =
  | 'admission_denied' | 'admission_threw' | 'admission_timeout'
  | 'admission_invalid' | 'admission_missing' | 'admission_stale'
  | 'admission_not_ready' | 'admission_unsupported'
  | 'admission_mode_ungranted';

type AdmissionVerdict =
  | Readonly<{ store: false; mayWake: false; reason: RefusalCode }>
  | Readonly<{
      store: true;
      mayWake: boolean;
      replyIntent?: HostReplyIntent; // opaque; validated by the host
      stamp?: HostNormalizedStamp;  // a value, NOT a metadata patch
    }>;

type LaneItem = {
  'channels/incoming': ChannelIncomingMessage;
  'push/event': PushEventParams;
  'inference/request': McplInferenceRequestParams;
};
type AdmissionInput = {
  [L in AdmissionLane]: Readonly<{
    connection: ConnectionKey;
    lane: L;
    item: DeepReadonly<LaneItem[L]>; // detached, untrusted, pre-stamp input
    signal: AbortSignal;
  }>
}[AdmissionLane];
type AdmitInbound =
  (input: AdmissionInput) => AdmissionVerdict | Promise<AdmissionVerdict>;

type BoundAdmission = Readonly<{
  connection: ConnectionKey;
  admit: AdmitInbound;
}>;
type InboundAdmissionConfig = Readonly<{
  timeoutMs: number; // required, finite positive bounded integer
  bind: (key: ConnectionKey) => BoundAdmission | undefined;
  isReplyIntent: (value: unknown) => value is HostReplyIntent;
  isNormalizedStamp: (value: unknown) => value is HostNormalizedStamp;
  initializeAttestation?: Readonly<{
    read: (initializeResult: DeepReadonly<unknown>) => unknown | undefined;
    matches: (attestation: DeepReadonly<unknown>) => boolean;
  }>;
}>;
// Public configuration addition:
// McplServerConfig.inboundAdmission?: InboundAdmissionConfig
// Internal adapters receive the required bit AND original ConnectionKey,
// not just a possibly-undefined callback looked up by channel id.
```

[prop] Field contract:

- `store:false` is refusal, not a successful discard: return the fixed reason, ignore all optional admission outputs, and do not call existing gates, acceptance observers, coalescers, processing modules, queues, inference, typing or status senders. `store:false, mayWake:true` is malformed, not a way to wake without storage.
- `store:true` permits the lane's existing admitted handling; it does not force a row to exist, bypass content checks, bypass deduplication, or make later processing infallible. For inference/request, which is not a context-ingest operation, it means permission to handle that request, not an instruction to persist its prompt. There is no new persistence behavior on that lane.
- `mayWake` is an additional ceiling. For ingest lanes, effective wake permission is `existingPermission && verdict.mayWake`. A false ceiling must survive queueing, coalescing, routing, tune-out/auxiliary processing and every subsequent scheduling decision; no downstream component may promote it. Skip wake-policy callbacks when the ceiling is already false. A true ceiling never raises a grant, overrides a false existing gate, or guarantees inference. On inference/request a false ceiling refuses the request with `admission_denied`, since silently completing an inference request without inference is not supported.
- `reason` is a closed enum, with no free-text detail. Accept branches must not carry it; refusal branches must carry it. Failures of the mechanism use the appropriate framework-selected enum value, never exception text or sender content. Results correlate using the existing message identifier, not copied content.
- `replyIntent` is a host-validated opaque capability/value. Call the configured host validator within the same bounded preflight; only literal true passes. Carry a successful slot unchanged in a private admitted envelope to host extension points. Do not decode, resolve, publish, schedule, acknowledge intent completion, put it in peer responses, or infer any reply destination from it. Its presence creates no permission to send. Its persistence is not promised.
- `stamp` is separately host-validated normalized data, carried only from the successful verdict in the private envelope. It is not a general metadata mutation facility. Do not expose either stamp or intent to peers or content-bearing diagnostics. Attach the normalized stamp only after final preflight success as described in section 6. Missing optional outputs are ordinary absence, not a fallback to sender claims.

[prop] Validate the complete verdict at runtime: exact booleans, valid discriminated branch, enum membership, no inconsistent/unknown fields, and host validation of optional opaque values. Use data-only snapshots; reject accessor-bearing or otherwise non-data host returns rather than executing getters. Protect validation exceptions and the whole awaited preflight with the same deadline. `undefined`, null, thenable rejection, invalid intent/stamp and unknown reasons are `admission_invalid` or `admission_threw` as appropriate, never acceptance.

[prop] Configuration ownership: use `McplServerConfig.inboundAdmission`, exposed through existing `FrameworkConfig.mcplServers`, rather than a global callback selected with `find`. `ChannelRegistryOptions` receives an internal connection-aware preflight adapter; the push handler and inference router receive corresponding adapters. The connection-level required/deny state is installed before reading traffic, not inferred from whether the adapter happens to exist. An unconfigured connection retains the old path even when another connection is configured.

[prop] Bind after successful initialize/optional attestation and before opening data admission. The synchronous host factory must explicitly return the exact issued key and a hook for that incarnation; a prior key is invalid. Do not copy an old closure as an automatic fallback. Reconnect invokes the factory again for a fresh key, so a host can deliberately reauthorize it, but the previous binding never survives by inheritance. Replacement objects get distinct instance tokens even if their ids and numeric epochs coincide. Registration by another connection of the same channel id conveys no admission binding.

[prop] A configured entry whose transport is absent has no usable binding and cannot admit anything. Initial bind failure/missing hook fails that configured connect closed; any inbound item reaching an incomplete configured adapter is refused `admission_missing`. Runtime disconnect retains the requirement, invalidates the binding and aborts pending preflights. Replacement/reconnect must re-attest when required and rebind before use. Removing a required hook must not silently remove the requirement. An explicitly removed connection cannot admit; changing a connection from required to unconfigured is an explicit host configuration/lifecycle change, not an automatic error fallback.

## 3. Ordering and option comparison (Q2)

[prop] For configured connections, retain protocol parsing, transport identity checks and existing authorization as prerequisites. They grant no additional authority to the hook. The hard guarantee is no message-caused framework admission effects before a successful verdict. Temporary immutable input, its bounded watchdog, and a refusal response are control bookkeeping, not stored context or admitted work. No content-bearing audit row, wake, typing, status or admission notice is permitted on hook refusal. Connection-close lifecycle effects occur independently; refusal cannot undo those or previously admitted sibling effects.

[prop] Strict ingress guard, before the existing push tap at `server-connection.ts:2439` and before any call that can hold the item at `:1039`:

```text
parse and identify originating instance + epoch
  -> configured? no: exact existing dispatch path
  -> yes: existing positive-grant authorization (read-only check)
  -> require current instance/epoch, live transport and ready admission planes
       not ready: refuse; do not put raw traffic into held-event queues
  -> route with original immutable connection key; suppress early push tap
  -> lane authorization / pure validation
  -> per-item host preflight (or unsupported-lane refusal)
  -> runtime verdict validation + revalidate epoch, grant, readiness and lane authority
  -> successful admission continuation; no await between final check and its first effect
```

[prop] Early traffic on a required connection is refused rather than staged before a verdict. This is an explicit opt-in difference, needed for the literal no-pre-verdict-queue guarantee; it is not a change to unconfigured staged startup. A peer must send after readiness or retry refused traffic. Do not report these items as accepted. Original epoch must be captured at line receipt for requests AND notifications, not reconstructed from `connection.transportEpoch` at callback entry. Configured traffic must not enter the old world-event replay path across epochs (`:529-548`, `:2529-2539`). Old-origin traffic is stale, not authorized by the replacement's grant. A pending-verdict envelope is not an admitted processing queue entry.

[prop] channels/incoming insertion point: retain the identity checks at `channel-registry.ts:1799-1818` and actual registration authorization at `:1834-1861`; then preflight immediately after that successful branch, before `:1863`. Supply an immutable snapshot of the raw lane item rather than constructing a stamped queued event early. Existing content validation/conversion can still reject after the host allows; allowing is not an acceptance receipt. Recheck the exact channel-entry identity after the await: removed/replaced/retargeted authorization is stale and must be reevaluated on a fresh delivery, not applied to a captured old entry.

[prop] Successful ordinary continuation: existing content checks -> markAccepted -> existing wake policy (only if allowed to wake) -> build event with private wake ceiling/opaque outputs -> existing source-envelope callback -> queue -> per-message result. ## 4. Failure modes and batching (Q4)

[prop] Every refusal below has the same admission-effect invariant: no context row, default/open/retarget change, queue entry, coalescing mutation, acceptance observer, module dispatch, wake, typing, status, or toolset notice caused by that item. Respond with fixed codes only; never serialize exception messages, verdict objects, metadata or peer text. This invariant concerns framework admission effects, not host callback effects or unrelated concurrent work.

| Condition | Required outcome | Tag |
|---|---|---|
| Valid refusal | channels/incoming item result `{messageId, accepted:false, reason:'admission_denied'}` or another enum refusal; continue siblings. | [prop] |
| Hook throws/rejects, including a host validator | `admission_threw`; discard outputs; continue siblings. | [prop] |
| Hook exceeds configured deadline | Abort signal; `admission_timeout`; ignore late resolve/reject permanently; continue siblings. Deadline includes all awaited verdict work. | [prop] |
| Malformed verdict/optional output | `admission_invalid`; do not coerce values or accept a partial verdict. | [prop] |
| Required hook absent, wrong-key binding or binding removed | `admission_missing` (or `admission_stale` for an obsolete installed key); never fall through to unconfigured handling. | [prop] |
| Closed/replaced connection, changed epoch, revoked grant, changed channel-entry authority or host stop during await | Abort/discard pending verdict; refuse stale/not-ready as applicable. Do not automatically retry under a new identity. | [prop] |
| Unsupported lane/combination or requested selected mode not granted | `admission_unsupported` / `admission_mode_ungranted`, before all effects; never erase selection and process normally. | [prop] |
| Peer disconnects before it can receive refusal | Record the local per-item refusal result, attempt only the original epoch-bound responder if usable; no delivery to the replacement. Wire receipt cannot be guaranteed on a dead transport. | [prop] |

[prop] channels/incoming remains itemwise and ordered. Allocate one result per visited item, correlated by its existing messageId; invalid identities follow the existing identity refusal. A denial, throw, malformed verdict or timeout neither authorizes siblings nor aborts the batch. Sequential evaluation bounds a bad item by one deadline; it can delay later siblings until that deadline but cannot indefinitely block them. Never memoize a successful verdict by channel id, stamp, intent or sibling result. Each fresh delivery/retry requires fresh admission; durable idempotency is not introduced here.

[src] The pinned coalesced path has a separate request-level exception: an already-admitted occurrence whose acknowledgement fails can stop later processing and return a request error (`channel-registry.ts:2014-2027`). That is not a preflight refusal.

[prop] Preserve that downstream exception; do not relabel already-admitted work as refused or claim rollback of earlier siblings. If the connection boundary changes during the batch, refuse all not-yet-admitted original-epoch siblings; already-admitted siblings retain their actual outcome. Lifecycle invalidation is not an atomic batch transaction.

[prop] After a valid verdict, revalidation and the first admission effect share a synchronous boundary. Subsequent awaits must carry the immutable original key and the wake ceiling and respect existing lifecycle checks; the preflight contract does not promise rollback of effects committed before a later disconnect. Callback promises resolving after cancellation are drained/ignored and cannot run a continuation that admits the item.

## 8. Extension points, not decisions (Q8)

- [prop] Generic context-only mode: an early lane support/authorization adapter would feed a future normalized internal delivery plan after admission but before markAccepted and all other effects. This is a separate policy from mayWake:false: suppressing inference alone does not currently suppress markAccepted/default changes. No context-only effect bundle or wire encoding is defined here.
- [open] Legacy host-verdict translation: a host adapter can later translate its legacy verdict into that normalized plan before preflight success. Which legacy values mean context-only, and how they combine with store/wake/reply intent, remain undecided. No special legacy vocabulary enters the framework in this task.
- [prop] Thread-aware replies: the opaque intent slot can reach a later host destination resolver. That resolver would plug in before publish dispatch; it must not reinterpret sender metadata as authority.
- [open] Thread destination representation/transport on publish, explicit-send policy and all outbound policy remain undecided. Existing threadId carriage is not a proposal for new transport behavior.
- [prop] Durable admitted-work recovery: a later extension could place a durable admission/intent boundary after successful preflight and before acceptance acknowledgement, then reconcile admitted-but-unfinished work on startup. The connection key and opaque intent can be inputs to that future boundary without being its storage design.
- [open] Durable store, ownership, transaction/acknowledgement ordering, crash idempotency, retention and replay authorization are not chosen. This proposal alone does not make an opaque intent durable or guarantee completion across restart. No new recovery implementation is authorized here.

## 10. Open questions and risks

[open] Independent review and design-owner approval are required before implementation; neither is claimed here. No implementation task or source modification is supplied.

[open] The strict configured ingress policy intentionally refuses pre-ready traffic and hint-bearing pushes and prevents old-epoch replay. These are necessary explicit limitations of this recommendation, not properties already offered by the pin. Hosts/peers that rely on staged delivery, watermark-based forwarding or hinted pushes need owner review before opting in. Supporting those combinations without weakening the guarantee needs another explicit design, not a silent fallback or broader refactor.

[open] Callback timeout values/maximum pending count, overload refusal and connection-level fairness need operational sizing before implementation. Each item has a finite deadline, but a large batch can still delay siblings by multiple deadlines. Bounded in-flight resource bookkeeping must never become an unbounded admitted-work queue.

[open] This investigation verified the cited legacy MCPL paths only. It did not verify a modern transport implementation, every module/auxiliary scheduling path, an actual host callback, a peer's attestation implementation, runtime timing or restart behavior. A future implementation must either cover each additional ingress/dispatch path with the same ceiling and preflight contract or reject required admission on it before connect; unsupported must never mean unguarded. The test outline is not a receipt that these invariants already hold.

[open] Remaining non-goals are unchanged: new delivery-mode wire encoding, legacy translation, durable intent/recovery ownership, publish thread transport, explicit-send policy and connector-specific behavior. This document makes no decisions about them. Stamp naming/schema and an agreed attestation protocol also remain unresolved; raw metadata is never a substitute for resolving those contracts.
