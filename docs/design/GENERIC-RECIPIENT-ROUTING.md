## 2. Recommendation: reuse destinations, add ownership, move policy out

[prop] Reuse `ChannelRef` and the existing logical-turn routing and publish pipeline. Add only (1) a trusted binding of a validated reply destination to admitted work, (2) ownership carried with that work and its typing indicator, and (3) T's explicit delivery-effect suppression and persisted classification. Do not add a recipient directory, a second channel registry, a generic routing DSL, a durable routing ledger, or framework-side connector adapters.

[src] The reusable primitives already distinguish two servers with the same channel id: `ChannelRef`, `destinationKey`, `sameChannel`, and registered `PublishDestination` (`U:src/mcpl/channel-registry.ts:665-706`). Keys are tuples, not colon-splitting. The latest inbound includes a thread (`U:src/mcpl/channel-registry.ts:2317-2345,2522-2532`); incoming messages have `threadId` (`U:src/mcpl/types.ts:1273-1284`). `TurnRouting` already lives across streams, with an existing `turnId`, a trigger channel and a locus (`U:src/framework.ts:1328-1405`). `deliverSpeech` deliberately takes a snapshotted locus, never a live fallback (`U:src/mcpl/channel-registry.ts:6090-6182`).

[src] These primitives are not sufficient as-is. `PublishDestination` contains no thread; `ChannelsPublishParams` contains no thread (`U:src/mcpl/channel-registry.ts:677-681`; `U:src/mcpl/types.ts:1254-1259`). R puts an extra `threadId` into the publish request without extending that public type (`R:src/mcpl/channel-registry.ts:6087-6094`). Upstream typing is channel-keyed and has no owner (`U:src/mcpl/channel-registry.ts:2225-2302`). A wake veto still permits a locus update (`U:src/admission/admit.ts:105-107`). A frozen **channel** is therefore not yet a frozen reply destination with context-only semantics.

## 3. Ownership and connector contract

### 3.1 Three authorities, not a renamed bridge

[prop] **Connector** owns platform interpretation: ids, thread roots/topics, edits, bot/human classification, authenticated transport, platform ACLs, receipt/dedupe behaviour, and actual delivery/typing. It registers ordinary MCPL channels and supplies inbound `channelId`, `messageId`, optional `threadId`; these are untrusted routing evidence until admitted. Where each topic/thread already is a registered MCPL channel, use its `ChannelRef` directly and omit `threadId`. Do not create synthetic thread channels merely to bypass missing publish negotiation.

[prop] **Host application** chooses per-connection required admission, authenticates the connector/recipient, owns read/auto-reply/explicit-send policy, validates raw evidence, and translates any legacy envelopes. It installs W's binder and validators, and a routing resolver for admitted intent. It can narrow permission but cannot raise an MCPL grant. It chooses which connections require an admitted automatic reply destination; absence on one of those connections means no automatic send, not “use latest inbound”. It may opt in two or more connectors simultaneously under arbitrary configured ids.

[prop] **Framework** owns connection-instance/epoch identity, grant and registered-channel enforcement, ordering, immutable envelope carriage, scheduling/turn ownership, destination equality, typing cleanup, publish outcomes and trusted persisted classification. It never selects a policy by connector name, checks a platform regex, infers mention authority from text, or re-accepts a metadata envelope at a downstream queue site. The host adapter produces decisions; the runtime applies them once.

### 3.2 Wire promises and minimum additions

[prop] Prefer ordinary MCPL channels plus existing grants (`channels.register`, `channels.incoming`, `channels.publish`, `channels.typing`). Threadless or thread-as-channel destinations need **no recipient wire capability**. Frozen-turn routing is a host runtime guarantee, not a privilege minted by a peer capability.

[prop] When a registered channel contains separately addressed threads, propose one versioned, connector-neutral **local interoperability extension**, `capabilities.experimental.replyRouting`, outside the standard MCPL manifest. Version 1 declares `publishThreadId: true` and `typingThreadId: true`; it means the peer will honor the optional top-level `threadId` on the existing `channels/publish` and `channels/typing` methods exactly, and reject unsupported/invalid targets rather than posting to the channel root. The host offers only the fields it implements; a configured threaded-reply profile requires the full agreed version/fields before opening admission. A profile not using typing need only require the publish field. No bot id, access list, implicit wake grant, provenance guarantee, or blanket status promise is part of this extension.

[prop] This is transport support, not authentication or authorization: publish still requires the current `channels.publish` grant and connector ACL; typing still requires `channels.typing`. The optional thread string is opaque to the framework, nonempty and bounded by the general protocol limits; absent means exactly the registered channel, never the most recent thread. No field is sent to an old peer that might silently ignore it. Failed/missing/partial/wrong-version negotiation fails the configured profile closed. Ordinary unconfigured channels remain usable unchanged.

[open] W specifies reading/checking an initialize result, not adding a host offer (`W:172-182`). A minimal generic host-controlled initialize-extension offer facility (data-only values; cannot override MCPL capabilities or grants) is therefore an explicit dependency if that facility is absent at implementation time. The connector identity expectation can stay in a host-private attestation agreed with that connector; it must not become a bot identity field in the generic runtime. M1 covers the final public names and standardization. This document's local extension spelling is a proposal, not existing MCPL vocabulary.

[prop] For T mode, use exactly its sibling advertisement `experimental.mcpl.channels.contextOnly`, grant `channels.contextOnly`, and per-message `delivery: "context-only"`, not a subfield of the boolean `channels.incoming`. Require both incoming and contextOnly grants; echo applied delivery in each accepted result; reject other types/values with `invalid_delivery`, missing grant with `capability_denied`, and coalesce or a normal-wake tag with `unsupported_combination`. Preserve ordered per-message results. Do not silently drop the selector. Do not list the new leaf in feature-set `uses` until the corresponding SPEC vocabulary change is accepted (T:37-44). U's decoder and closed vocabulary need additions and compatibility tests (`U:src/mcpl/capability-grant.ts:38-104`).

[prop] Upstream MCPL SPEC work should cover §14.1 negotiation/grants, §14.3 delivery field/results and optional publish/typing thread target, §14.5 current-grant/registered-channel checks, and §6.2 `uses` vocabulary. Keep local-vs-standard negotiation explicit during migration; do not imply acceptance of `replyRouting` by the current spec. A registered thread-channel may eventually make the thread extension unnecessary for a connector; that is connector representation, not a second framework route.

### 3.3 W admission and the new outbound consumer

[src] W makes `replyIntent` opaque, optional, private, and non-authorizing; it explicitly forbids its admission layer from resolving or publishing it and promises no persistence (`W:71-77,211-218`). Neither `mayWake:false` nor its unspecified stamp implements T's effect bundle. K proposes a concrete `ReplyScope`, but its outer-handler insertion is too late to precede the early push tap/transport holds (`K:13-20`; `W:112-147`).

[prop] Keep W's verdict API intact. Add an explicit **post-verdict host routing consumer**: while still before any admission effect, after full W verdict validation, the configured host resolver receives the private admitted intent, original connection key, and validated lane identity. Within the same bounded/cancellable preflight it returns a data-only reply destination or a fixed refusal. The admission module itself never interprets intent. The consumer validates/detaches the output, rechecks connection/grant/registration, and commits it to the private admitted-work envelope with the first admission effect in one synchronous boundary. Host effects inside a resolver are not rolled back; impose W's no reentrancy and cancellation constraints.

[prop] The reply destination reuses `ChannelRef` with optional `threadId`; registered labels may be attached to `PublishDestination` for diagnostics, never equality. Server identity is assigned from the connection key, not returned by untrusted metadata. V1 auto-reply targets must be on that connection and match the admitted channel (or an explicitly host-resolved registered thread channel on it). Cross-connector replies are explicit sends, outside this auto-reply contract. Reject unsupported thread transport before waking a required-reply turn. Validate automatic-send permission independently of read/wake permission; preserve read-only storage where host policy permits it.

[prop] The resulting private record contains original connection key, immutable destination when authorized, a framework-minted admitted-work identity, and the delivery-effect ceiling. The runtime attaches existing `TurnRouting.turnId` when work opens a logical turn. Do not introduce K's second public scope-id system: distinguish work identity (pre-turn), turn identity (existing), and destination equality (server/channel/thread). Copy the immutable binding through private request/queue/continuation fields, inaccessible as model/module-authored request properties. A string-identical object from a tool result or sender metadata has no binding. Raw input, host stamp, effect plan and resolved destination remain separate values.

[prop] Resolution failure is never “missing optional intent, use default”. On a required-reply wake: invalid/missing destination refuses admission (fixed code); an authorized read-only verdict may instead store with no wake/destination, as deliberately chosen by host policy. A genuine context-only plan always suppresses automatic reply/typing even if an otherwise valid intent was returned. Host intent is not serialized to peers or persisted as replay authorization.

### 4.2 Delivery plan and persistence

[prop] Use a closed internal effect plan, not a general policy language. Normal delivery preserves existing decisions; the temporary legacy compatibility profile suppresses wake, locus/anchor, conversational-injection and presence effects but leaves existing transport-open evidence unchanged; full context-only suppresses those effects **and** open repair. These are upper bounds: none enables an effect that existing grants, lifecycle or policy disallow. Only a configured host compatibility adapter can select the temporary profile; neither metadata nor a generic false wake gate can select it. A validated wire context-only selection cannot be weakened by a host intent or compatibility profile.

[prop] T's native selector applies to every connection granted that capability, even one without a custom W hook. Such a connection uses the framework's pure selector/authorization validation and effect plan, not a fabricated host verdict. W's exact no-hook path is unchanged when neither the selector nor the enabled T storage profile applies; T's selected-mode effects and reserved-key collision delta are explicit opt-ins. If a required W hook is installed as well, its store refusal wins and its wake ceiling intersects the plan.

[prop] A wire-selected context-only mode is independent of an ordinary wake veto. A successful W verdict yields an upper wake bound; T mode additionally forbids actual/desired-open changes, latest-inbound/default/parked-anchor changes, conversational injection, repin, explicit-send suppression reset, conversational module inference, typing and status. Registered/authorized closed or tuned-out channels may still store under existing storage/view policy; unknown channels remain refused. Maintenance/indexing/compaction is not conversational inference and is not promised free. No generic mention-only policy is introduced.

[prop] Use a host-owned, versioned stored classification (working storage name `inboundDelivery`, version 1; proposed members `version`, `mode`, and `conversational`, with mode limited to normal/context-only and context-only requiring conversational=false) in the existing stored-row metadata mechanism, not a connector-set marker. The schema records applied mode and the minimal conversational-effect classification needed for history predicates, not the opaque intent or an executable destination. The temporary compatibility profile stores normal/conversational=false; the separate transport-open choice is live admission policy, not something history replay may execute. Host writes it last from the private envelope; remove sender collisions at the reserved key on **every** lane, including normal/push ingress, and ignore similarly named nested tags for authority. Refusals write no stamp. Ordinary historical rows without a stamp retain existing semantics; malformed future-version stamps must not be promoted to conversational authority during reconstruction.

[open] W's feature-off “unchanged metadata” promise and T's all-lane reserved-key stripping cannot both be literal for a sender already using that key (`W:184-196,220-229`; T:48). Recommended resolution: scope global reservation to the explicitly enabled T storage profile, document the single collision delta, and keep W-alone feature-off unchanged. O1 settles separate opt-in phases and the one-way stamp rule (no downgrade over stamped history); the final reserved name, collision handling and compatible-reader details remain open under M2, not an unannounced generic cleanup.

[prop] Persist the classification at the same row-write boundary as accepted content, and preserve it through sharding, deferred writes, queue reconstruction and history reads. Reuse reserved host metadata patterns, not a second ledger (`U:src/stored-injections.ts:21-35,63-78`; `U:src/framework.ts:17061-17074`). Proposed compaction rule: summaries are not new conversational arrivals; maintain per-source-row classification/provenance for any history predicate needing last conversational input. A mixed summary cannot mark all covered rows normal or take its own creation time as a new reply anchor. If the context-manager API cannot preserve/query that provenance, require its companion change before enabling T; do not infer classification from summary text.

[open] Store/compaction compatibility is not proven by these framework sources; T explicitly leaves it open (T:48,84-92). Qualification must restart a process after storing context-only rows, reconstruct deferred queues, compact mixed histories, and verify the same repin/suppression/last-injection decisions. Do not downgrade to a reader that ignores the classification; do not restore stale history over accepted rows. This persistence requirement is **not** durable automatic-reply recovery: no reply intent or unfinished turn is resurrected from history. That latter feature needs a separate transaction, replay-authorization and idempotency design.
